# Как подключить Google Calendar

Инструкция для человека, который ни разу не открывал Google Cloud. Займёт минут 15. В конце у тебя будет **Client ID** — строка вида `123456789012-abc...xyz.apps.googleusercontent.com`. Её нужно вставить в `src/config.js`.

Client ID не секрет: он и так виден любому, кто откроет сайт. Защита в другом: Google пускает вход только со страниц на адресах, которые ты сам разрешишь в шаге 5. **Client secret** Google тоже покажет, но он не нужен. Никуда его не копируй и в репозиторий не клади.

Меню Google Cloud иногда переименовывают. Если пункта нет на месте, ищи его строкой поиска вверху консоли.

## 1. Создать проект

1. Открой https://console.cloud.google.com и войди тем Google-аккаунтом, в чьём календаре лежат пары.
2. Если Google попросит принять условия — выбери страну и согласись.
3. Вверху слева, рядом с логотипом, есть выбор проекта. Нажми его → **New project** (**Создать проект**).
4. Название: `day-planer`. Organization / Location оставь как есть → **Create**.
5. Через несколько секунд проект создан. Убедись, что вверху выбран именно он.

## 2. Включить Google Calendar API

1. Меню ☰ → **APIs & Services** → **Library** (**Библиотека**).
2. В поиске набери `Google Calendar API`, открой его → **Enable** (**Включить**).

## 3. Экран согласия (что Google покажет при входе)

1. Меню ☰ → **Google Auth Platform** (в старом интерфейсе — **APIs & Services → OAuth consent screen**). Нажми **Get started**.
2. **App information**: имя приложения `Планер`, **User support email** — твоя почта → **Next**.
3. **Audience**: выбери **External** → **Next**.
4. **Contact information**: снова твоя почта → **Next**.
5. Поставь галочку согласия с правилами → **Continue** → **Create**.

## 4. Тестовый режим и ты как тестовый пользователь

Приложение остаётся в режиме **Testing**. Так Google не требует проверки, но пускает только людей из списка.

1. В **Google Auth Platform** слева открой **Audience**.
2. **Publishing status** должен быть **Testing**. Кнопку **Publish app** не нажимай.
3. Ниже, в **Test users**, нажми **Add users**, впиши свою Gmail-почту → **Save**.

## 5. Разрешение на чтение календаря

1. Слева **Data access** → **Add or remove scopes**.
2. В фильтре найди `calendar.events.readonly`. Полная строка: `https://www.googleapis.com/auth/calendar.events.readonly`. Отметь её.
3. **Update** → внизу страницы **Save**.

Это разрешение только на чтение событий. Приложение не сможет ничего создать, изменить или удалить в календаре.

## 6. Создать Client ID

1. Слева **Clients** → **Create client** (в старом интерфейсе — **APIs & Services → Credentials → Create credentials → OAuth client ID**).
2. **Application type**: **Web application**.
3. **Name**: `day-planer web`.
4. **Authorized JavaScript origins** → **Add URI** → впиши ровно:
   ```
   https://fatoom333.github.io
   ```
   Без `/day-planer/` на конце и без косой черты. Origin — это только схема и домен, путь в него не входит. Если впишешь путь, Google не примет адрес.
5. Если хочешь проверять вход на компьютере через `python3 -m http.server 8000`, добавь второй URI: `http://localhost:8000`.
6. **Authorized redirect URIs** оставь пустым: этот способ входа их не использует.
7. **Create**. Появится окно с **Client ID** — скопируй его. **Client secret** не копируй.

Потерял ID — он всегда виден в **Clients** в строке `day-planer web`.

## 7. Вставить Client ID в приложение

Самый простой путь: пришли мне Client ID в чат. Я вставлю его в `src/config.js`, подниму версию офлайн-кэша и запушу.

Руками:

1. На GitHub открой `src/config.js` → карандаш **Edit**.
2. Замени `YOUR_CLIENT_ID.apps.googleusercontent.com` на свой ID. Кавычки оставь.
3. Там же открой `sw.js` и увеличь `VERSION` на единицу, например `'v3'` → `'v4'`. Иначе телефон останется на старой версии без календаря.
4. **Commit changes** → влей ветку в `main` (см. `docs/deploy.md`).

## 8. Первый вход с телефона

1. Открой приложение → **Настройки** → **Календарь**.
2. В поле **Календари** оставь `primary`, если пары в основном календаре. Если пары в отдельном календаре, узнай его ID: Google Календарь на компьютере → ⚙ **Настройки** → слева нужный календарь → **Интеграция календаря** → **Идентификатор календаря** (вида `abc123@group.calendar.google.com`). Можно перечислить несколько через запятую.
3. Нажми **Загрузить пары на неделю**. Откроется окно Google: выбери аккаунт.
4. Google предупредит: **«Google hasn't verified this app»** («Приложение не проверено»). Для тестового режима это нормально, ведь приложение твоё. Нажми **Continue** (**Продолжить**).
5. Разреши просмотр событий календаря.
6. Пары появятся на **Сегодня** серыми плашками и на **Неделе**.

## Как это работает каждый день

- Пары сохраняются на телефоне на 7 дней вперёд и видны без интернета.
- Вход живёт до часа и только пока приложение открыто. После перезапуска для новой загрузки снова нужно нажать кнопку. Окно входа тогда обычно мелькает и закрывается само.
- Обновляй пары раз в неделю или когда поменялось расписание. Если на сегодня пары не загружены, «Сегодня» об этом напишет.
- **Выйти** отзывает доступ у Google и удаляет сохранённые пары с телефона.

## Если что-то пошло не так

| Что видишь | Почему | Что делать |
|---|---|---|
| `Error 400: origin_mismatch` или `redirect_uri_mismatch` | Адрес сайта не в списке origin | Шаг 6.4: ровно `https://fatoom333.github.io`, без пути |
| `Error 403: access_denied` | Тебя нет в тестовых пользователях | Шаг 4.3 |
| «Вход Google ещё не настроен» в настройках | В `src/config.js` осталась заглушка или телефон на старой версии | Шаг 7, и не забудь `VERSION` |
| «Календарь … не найден или нет доступа» | Опечатка в ID или календарь другого аккаунта | Проверь ID в настройках Google Календаря |
| «Браузер не открыл окно входа» | Chrome заблокировал всплывающее окно | Разреши всплывающие окна для сайта и нажми ещё раз |
| Пары не видны, а загрузка прошла | Событие отмечено «Свободен» или длится весь день | Такие события планер пропускает намеренно |
