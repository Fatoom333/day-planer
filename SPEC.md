# Динамический планер — спецификация v1

## Цель

Планер на день и неделю для телефона, который ставится как приложение. После каждого события («проснулся в 10», «сделал», «пропустил») он пересчитывает остаток дня. Со временем он узнаёт, во сколько раз ты ошибаешься в оценках, и закладывает поправку.

## Решения (приняты)

| Вопрос | Решение | Почему |
|---|---|---|
| Кто пересчитывает | Детерминированный JS в странице, без LLM | Арифметика времени, нужна предсказуемость, пересчёт бесплатный |
| Где живёт | Статическая PWA на GitHub Pages, отдельный публичный репо только с кодом | Ставится в Chrome как приложение, не нужен сервер |
| Где данные | IndexedDB на телефоне + `navigator.storage.persist()` + экспорт/импорт JSON | Задачи не покидают устройство. Бэкап защищает от очистки браузером |
| Пары | Читаются из Google Calendar через OAuth, scope `calendar.events.readonly` | Расписание уже синхронизировано туда. Двигать пары нельзя |
| Порядок | Всегда авто-сортировка; ручная перестановка — поправка до конца дня | «Автоматически, с возможностью ручками поправить»; вечные правки устаревают |
| Дробление | Флажок на задаче, по умолчанию выкл. | «В общем случае не дробятся, бывают исключения» |
| Не влезло | Планер спрашивает: завтра / в конец недели / удалить / уменьшить оценку | Решение пользователя |
| Стиль | Новый, спокойный, светлый + тёмная тема по системе | Выбор пользователя |

## Модель данных

- **Task**: `id, title, estimateMin, priority (1 высокий…3), deadline? (дата), notBefore? (дата), category, splittable (по умолч. false), status (todo|doing|done), startedAt?, finishedAt?, actualMin?, createdAt`
  - `notBefore` — раньше этой даты задача не планируется. Его ставят «завтра» и «в конец недели» из блока «Не влезает» и кнопка «Пропустить».
  - «Пропустить» = «не сегодня»: `notBefore` = завтра, в поправку не идёт.
  - «Готово» без «Начать» не пишет `actualMin`, и в поправку такая задача не идёт.
  - Выполненные задачи переезжают в историю, поправка считается по ней.
- **DayOverride**: `date, order[]` — снимок ручного порядка на сегодня; на другой день игнорируется.
- **FixedEvent** (из календаря, только чтение): `start, end, title`. Кэшируется, чтобы работать офлайн.
- **DayState**: `date, wakeAt?` (фактический подъём).
- **Граница дня — 04:00.** До 04:00 ещё «вчера»: минуты идут дальше 1440. `sleepAt` раньше подъёма означает следующие сутки, но не позже 04:00.
- **Settings**: `defaultWake, sleepAt, bufferMin (10), calendarIds[]`.

## Алгоритм пересчёта (чистая функция, покрыта тестами)

`plan(now, dayState, fixed, tasks, factors, settings) → { slots[], overflow[] }`

1. Окно дня: от `max(now, wakeAt ?? defaultWake)` до `sleepAt`.
2. Занятое время: пары из календаря и текущая задача в работе (от `now` до `startedAt + прогноз`). Если прогноз уже истёк, задача занимает ещё 10 минут.
3. Свободные интервалы = окно минус занятое, с буфером `bufferMin` вокруг пар.
4. Прогноз задачи: `estimateMin × factor[category]`.
5. Порядок: авто-ключ приоритет → дедлайн (раньше выше; просроченные отдельно не поднимаются) → дата добавления. Если сегодня задачи перетаскивали, действует снимок ручного порядка; новая задача встаёт сразу после последней более важной (или наверх). Завтра снова чистая авто-сортировка.
6. Жадная укладка: каждая задача встаёт в первый интервал, куда помещается целиком. Если стоит `splittable`, задача режется по интервалам кусками не короче 25 минут (последний остаток может быть короче). Интервалы короче куска пропускаются.
7. Не поместившиеся задачи попадают в `overflow` и в UI выводятся вопросом.

**Поправка на прошлое:** `factor[category]` — медиана `actualMin / estimateMin` по последним 20 завершённым задачам категории. Нужно минимум 5 точек, иначе берётся 1.0. Значение ограничено диапазоном 0.5…2.5.

**Неделя:** тот же `plan` прогоняется на 7 дней вперёд с утра по умолчанию. Первый день — сегодня от текущего момента. Не влезшее в день N переходит в день N+1. Задача с `notBefore` подмешивается в очередь в свой день по авто-ключу. Результат — прогноз «что влезет в какой день», а не жёсткий план.

**Конец недели** — ближайшее воскресенье; если сегодня воскресенье — следующее.

## Экраны

1. **Сегодня**: лента слотов (пары серым, задачи карточками). Крупные кнопки «Начать» и «Готово», сверху кнопка «Проснулся». Блок «Не влезает» с вопросами.
2. **Неделя**: 7 дней, в каждом загрузка и список задач.
3. **Задачи**: список всех задач с правкой (оценка, приоритет, дедлайн, категория, дробление) и удалением. Быстрое добавление (название + оценка + приоритет, остальное по раскрытию) стоит на экране «Сегодня».

Перетаскивание на «Сегодня»: карточка, брошенная на другую, занимает её место в очереди. Это не место на шкале времени, потому что жадная укладка может поставить мелкую задачу раньше.
4. **Настройки**: календарь (войти/выйти), время сна, экспорт/импорт.

## Безопасность

- Весь текст выводится только через `textContent`, без `innerHTML` с данными пользователя или календаря.
- Строгий CSP: `script-src 'self' https://accounts.google.com`; `connect-src 'self' https://www.googleapis.com`.
- OAuth-токен хранится только в памяти и не пишется в хранилище. Scope только на чтение. Client ID публичный по природе, секрета нет (implicit/token flow GIS).
- Импорт JSON валидируется по схеме: типы, длины, диапазоны. Лишние поля отбрасываются.
- Без сторонних зависимостей, кроме скрипта Google Identity Services.

## Вне v1

Синхронизация между устройствами, повторяющиеся задачи, уведомления, запись в календарь.

## Критерии готовности v1

- Тесты `plan()`: проспал, сделал быстрее, задача затянулась, всё не влезает, пара посреди дня, пустой день.
- Страница ставится в Chrome на Android, открывается офлайн, данные переживают перезапуск.
- Пары из календаря видны на экране «Сегодня».
- Security-проход и semgrep/gitleaks чистые.
